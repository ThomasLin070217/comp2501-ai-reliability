# 给项目组成员的复核指南

目前的来源检查、材料筛选和非标准答案判分由 Codex 完成。仓库公开和脚本通过不代表独立人工审核已经完成。下面是组员可以直接执行的复核流程；请保留原始结果，用新的审阅文件记录不同意见。

## 先确认我们到底测了什么

阅读 [实验条件](README.md) 和 [执行偏离](protocol/deviation-audit.md)。实验只比较无搜索的日期事实问答，不测训练效果，也不比较 RAG、投票或完整 CoVe。

每个接收单元包含一条初始回答和六条平行复核分支。C3 看见初始回答和与 C2 相同的错误建议，**没有看见 C2 的输出**。展示案例时应说“C2 答错、C3 答对”，不能说“模型先经过 C2，再被 C3 救回来”。两次重复共享题目与材料，不能当作两道独立题。

## 逐条核对评分边界

正式数据完成后，先读 `reports/main/unfiltered_diagnostic/blinded_format_review.json`。该界面隐藏模型、条件和任务 ID，但给出题目、参考答案及原始输出。措辞本身可能透露条件，因此不应称为完全盲法。独立复核者先写自己的判断，再打开 `data/main_adjudications.json` 比较，不预先阅读总体效应。

每条记录至少保存：`review_id`、自己的判断、理由、审阅人、时间、是否已看过原判决。主要规则：

- 题目要年、月还是完整日期？更精确的答案只按题目要求的精度比较；不够精确的输出需要复核。
- 明确拒答与答错分开。空答案且 `abstain=true` 是拒答；既写答案又声明拒答，必须结合完整文字判断并记录边界。
- 答错是否恰好等于预设错误日期？其他错误不能计为采纳指定错误。
- 多个互相冲突的日期、范围、否定句或错误 JSON，不能仅因字符串包含正确年份就判对。
- 评分针对最终日期答案；解释里的其他事实错误另作案例记录，不偷偷改变主评分对象。

有合理争议时保存替代判法及理由，用敏感性分析同时报告。不要只采用能让结论更好看的版本。

## 核对参考答案与材料

从 `data/main_questions.jsonl` 读取完整题目、参考日期和 `verified_source_url`。打开来源后，核对它描述的实体、事件和所需日期，而不只是搜索年份。尤其注意发布日期与事件发生日、签署与生效、多个同名地点、年/月/日顺序。SV1441 的地点歧义已单列在 `data/main_preanalysis_caveats.json`。

对建议材料，先区分两个问题：日期目标是否符合指定条件？解释是否夹带了额外的未经支持的事实？故意错误的建议不是参考答案。正确目标材料也不等于每句背景断言都经证实。任何新增排除意见放在独立复核文件，保留本轮冻结的 120 题主结果，另作透明的敏感性版本。

## 检查数字能否复算

按照 [REPRODUCE.md](REPRODUCE.md) 离线运行分析和请求审计，无需 API 密钥。复算输出写新目录。确认原始采集包含 120 题、720 套七分支单元、5,040 条接收响应；不存在缺失分支、重复任务或跨分支上下文污染。主分析的可判分单元数另见 `reports/main/output_quality.json`，不能把接口正常结束当作内容一定完整。比较数值及内容哈希，不要求重新生成的时间戳相同。

主效应分母是“初始答对”的单元，纠错控制的分母是“初始答错”的单元。5,040 是响应数，不能用于宣称有 5,040 个独立样本。读置信区间时保留其不确定性；未发现差异不等于证明等效。

## 展示前最后检查

用完整统计说明频率，用可追溯案例解释行为。报告有利与不利结果、拒答变化、用量、开发警报的执行偏离和独立审阅状态。关于外部检索与证据核验的建议，应明确标成后续待测方案，不能说本轮已证明它最有效。

本指南不要求修改主数据，也不代表已经有人完成上述复核。成员完成后再记录实际覆盖的题号和记录数；抽查不能写成全量人工审核。
