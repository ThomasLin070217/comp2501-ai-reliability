# 接收输出质量补记与分析处理

记录时刻：2026-09-30T18:07:05.602794+00:00

正式采集中、尚未查看正式聚合结果时，隐藏元数据的格式复核发现一条 API 报告正常结束、正文却只有 `{"answer": "Februar` 的输出。原响应的 `stop_reason` 为 `end_turn`，用量为 8 个输出 token；并非脚本因 max_tokens 判定的截断。无法从它判断完整月份和年份，更不能推测其本来会回答什么。原始数据保留，不重新调用。

既有采集器只能按接口结束标记检测截断，冻结分析器也没有“不可判分输出”的专门分类。这是实测发现的处理缺口。采集曾短暂停下检查；确认接口正常返回但内容不可用后，保留冻结接收流程继续完成计划调用，不改变题目、提示、材料、模型或调用数。

处理规则在查看条件标签及聚合效应前记录：完整答案虽有格式问题时仍可语义复核；只有确实无法恢复完整答案、又没有明确拒答的输出标为 `unscorable_output`。不把它判成事实错误或明确拒答。全部此类记录统一适用，不因模型、实验组或是否有利选择。

主结果使用具有七条可判分响应的完整配对单元；若一条不可判分，移出该题–模型–重复的全部七条，仅影响分析，不删除原始数据。受影响记录和配对单元单列。保存未经过这一质量过滤的原冻结分析输出，保留 pending 标记；不能把它当作有效完整分析。另报告将此类失败按未答出计入的敏感性结果，以及整题排除版本，说明结论是否依赖该处理。

这是正式采集后的分析处理修订，并非全部预注册。冻结主分析代码本身不修改，质量过滤使用独立文件和包装脚本。接口成功数、可判分响应数、分析单元数分别报告。HTTP 成功不等于答案可用。
