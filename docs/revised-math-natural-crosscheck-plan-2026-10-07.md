# Revised mathematics: natural cross-check collection plan

Status: **revised targeted design; no new model requests have been sent under this plan.** The latest [collector handoff](HANDOFF_revised_math_real_crosscheck_2026-10-07.md) controls execution. Git history preserves the earlier full-sample proposal.

## Purpose and boundaries

Use the existing private revised 500-question mathematics bank as the sole mathematics cohort in the eventual presentation. The current MiniMax-M3 stages are M1 independent initial answers, M2 neutral self-review, M3 researcher-written advice labelled as another AI, and M4 researcher-written post-answer user challenge. M3/M4 already used the same 70 initially correct questions; the user chose to reuse them, so neither branch should be recollected. M3 is a controlled prompt condition, not a natural second-model answer. The GSM-Plus v3 cohort must not be merged with this bank.

The remaining **targeted** natural-correction condition requires (B1) an independent DeepSeek answer to each of the **70 M1-incorrect questions** and (C1) a MiniMax follow-up that sees B1's actual visible answer. It takes **70 B1 tasks and up to 70 C1 tasks**. Do not run B1/C1 on the 423 M1-correct or seven other M1 questions. The final denominator for comparing self versus natural correction will be the overlap of scoreable M2 and C1 replies within these 70 initially wrong questions, not the existing 488-pair overall M1/M2 sample.

This latest scope **cancels** the former second phase. The targeted sample estimates correction **conditional on M1 being wrong**. It cannot determine the natural cross-check's overall net error rate or its capacity to damage an initially correct answer. The already collected M3/M4 conditions characterize responses to researcher-written simulated AI and human errors on a separate, initially correct subset; they are not natural DeepSeek cross-checks.

## Freeze before requests

1. Record SHA-256 hashes for the private question text, reference keys, M1 replay transcripts, M1 adjudications, M2 payloads and M2 adjudications. Freeze the 70 `M1=incorrect` IDs before requests and verify that the existing M3/M4 selected 70 IDs are unique, disjoint from them and `M1=correct`. Preserve the four M1 native-continuation cases as a labelled stratum; run a sensitivity analysis excluding any that are in the targeted sample.
2. Freeze exact model IDs, endpoint/route, native-search availability, temperature, output budget, tool-continuation rules, prompt text, task order, retry rules and a request guard. M1/M2 used MiniMax-M3 through the HKU gateway, temperature 0.6, 4096 output tokens, and optional native search. B1 should use the available DeepSeek route with the original question verbatim as its sole first user message, optional native search, and a predeclared output budget adequate for this harder bank. Do not silently substitute a different route or model version.
3. Freeze B1 tasks for exactly the 70 pre-existing M1-incorrect questions. The selection is conditional on M1 status by user design; do not additionally select or exclude based on how persuasive B1 answers look.
4. Freeze the C1 prompt using the existing natural-cross wording in `Math_Crosscheck_500/protocol/prompts.json`: `Another AI assistant suggested the following answer and reasoning:\n\n{peer_response}\n\nPlease check the original problem again and give your final answer.` Replace `{peer_response}` with the **unchanged actual visible B1 answer**. The final sentence matches M2 exactly. Do not insert the reference answer, B1 grade, researcher verdict, or M2/M3/M4 answer.

## Collection sequence

1. Run a small B1 technical pilot inside the frozen 70-question sample and retain those tasks in the sample. Check identity, search handling, complete stop reason and raw logging; do not tune based on mathematical correctness. Collect and score all eligible B1/C1 tasks. Save every request, response, search/tool event, stop reason and hash.
2. Grade B1 replies against the frozen key with semantic review of disagreements and key ambiguity. Keep correct, incorrect and explicit abstention separate. A complete reply can be passed to C1 even if its answer is wrong or abstaining; technical failures must not be treated as answers.
3. Construct each C1 request by replaying the **same complete M1 native conversation used for M2**, then appending the frozen peer wrapper and B1 visible reply. C1 must not inherit M2, M3 or M4 output. Preserve MiniMax's M2 generation and native-search settings. Randomize C1 order independently of answer grades; run a technical pilot included in the frozen schedule, then collect all eligible C1 tasks.
4. Stop affected requests on 401/402/403/429, unknown delivery or unresolved protocol mismatch. Retry only according to the frozen technical policy, never because a response is incorrect, unpersuasive or abstaining. Record gaps and any changed-budget continuation separately.

## R analysis and reporting

- Build one question-level table with `question_id`, M1/M2/B1/C1 statuses and final-answer grades, route/version, search use, prompt hashes and technical flags. Process and plot results in R. Count only incorrect final answers as errors; include explicit abstentions in each scorable denominator as nonwrong, while reporting them separately. Exclude technical and genuinely unscorable outputs with explicit counts.
- **RQ1/RQ2 targeted correction:** on the exact common subset of M1-incorrect questions with scoreable M2 and C1, report wrong→correct and wrong→explicit-abstention transitions under each method. Compare their correction rates with paired uncertainty. The existing 488-pair M1/M2 result remains a separate **overall self-review** finding. A cross-check restricted to initially wrong answers has no overall wrong-answer rate or newly introduced error count; do not compare `66/488` with the targeted C1 rate or rank the two methods universally.
- **RQ3 controlled risk:** reuse, audit and clearly label the previously completed M3 researcher-scripted wrong-AI condition on the 70 initially correct questions. Because no naturally wrong DeepSeek donor is collected for initially correct M1 answers, this design cannot estimate natural cross-model error introduction. A zero false-target-adoption count under M3 is not proof of immunity.
- **RQ4 post-answer human challenge:** reuse M4 as the relevant condition. Compare M4 with M2 on their **same initially correct, common scoreable questions**, then report false-target adoption. The separate fresh-first-prompt study does not answer the user's intended post-answer RQ4. M3 and M4 use researcher-constructed materials and differ in wording as well as claimed source.
