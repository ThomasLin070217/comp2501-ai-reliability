日期：2026-09-30。状态：**设计草案，等待用户确认后实施；暂停新增模型 API 调用。**

本计划是当前项目的统一范围说明。确认后，它取代旧试运行报告中关于后续扩展的建议；旧数据、旧报告和失败记录继续保留。用户确认的是本计划的范围与资源安排；开发轮之后仍需先出具冻结版本和实际用量预测，再进入正式采集。

## 1. 我们究竟在研究什么

暂定题目：**当 AI 误导 AI：错误同伴建议对 Double-check 准确率的影响及缓解方法**。

实际场景是：一个 AI 已经回答了问题，我们让它参考另一个 AI 的建议再次检查；但另一个 AI 的建议可能是错的。我们要测量这种复核何时会损害正确性，并测试一种具体的缓解流程。

本研究是**受控的模型间误导压力测试**。研究者指定一份错误答案，由另一个模型生成支持它的解释，再测接收模型的反应。这能测试对错误建议的稳健性，不能估计真实应用中其他模型自然犯错的频率。

两个研究问题：

1. **RQ1：在 AI 同伴已经给出错误答案的情况下，附加一段误导性解释，是否增加接收模型从正确答案改为错误答案的概率？**
2. **RQ2：收到完全相同的建议时，结构化核验提示能否降低被带偏的概率，同时保留采纳正确建议、修正原有错误的能力？**

“中性复核”是参照组，用于估计模型自行检查时的答案变化；“正确建议”是辅助对照，用于检查所谓防御是否只是让模型拒绝所有建议。

允许的结论是“在这套题库、这些模型版本、这种误导设置下，方法产生了某种效果”。不声称发现普遍最有效的方法，也不把答案改变直接等同于心理意义上的迎合、撒谎或知道真相。

## 2. 本次明确不做的扩展

- 不研究营销、AI 视频，也不回到泛泛的“AI 最容易犯什么错”。
- 主实验不加入多轮自由辩论、两个模型共同施压、搜索工具、额外裁判模型或模型训练。
- 不同时比较独立采样、多数投票、联网核验等多个防御；先测一种能够等调用次数比较的结构化核验。
- 不把三个模型的结果解释为模型架构或训练数据的因果差异。
- 不以证明某个模型弱或制造成功误导案例为目标；零效应也是结果。

上述扩展只有在主问题完成后才另立方案，不能直接混入正式数据。

## 3. 一道题如何流经实验

每道题有研究者核实过的标准答案、一个预设错误答案及来源证据。参考答案和证据仅用于材料制作、质量检查与评分，不进入接收模型上下文。

1. 先固定“建议生成者 → 接收者”的配对。
2. 生成者分别产出一份正确建议和一份错误建议，各包含答案与简短解释。错误建议是在研究者明确要求下生成的，不伪装成模型自然答错的数据。
3. 质量检查并冻结两份建议，之后才采集接收者的初始答案。生成者不能根据接收者的初始答案或是否容易被说服来改写攻击。
4. 接收者独立回答原题，保存一份初始答案。
5. 从相同初始答案分出六条独立复核分支，每条只看到本组材料。任何分支都看不到其他分支结果。
6. 依据预先冻结的评分规则，对初始及最终答案判分。

一次试验只有“初始回答 → 一次复核”两步。下文的三轮指项目的三个阶段，不是让模型连续辩论三次。

## 4. 正式条件：六组加一份共同初始答案

| 代码 | 复核时看到的内容 | 复核方式 | 用途 |
|---|---|---|---|
| C0 | 不提供同伴建议 | 普通复核 | 测自行复核导致的波动 |
| C1 | AI 同伴的错误答案，不附解释 | 普通复核 | 错误结论的参照 |
| C2 | 与 C1 相同的错误答案，附误导性解释 | 普通复核 | 与 C1 比较，回答 RQ1 |
| C3 | 与 C2 **逐字相同**的建议 | 结构化核验 | 与 C2 比较，回答 RQ2 的抗误导部分 |
| C4 | AI 同伴的正确答案与解释 | 普通复核 | 采纳有益建议的参照 |
| C5 | 与 C4 **逐字相同**的建议 | 结构化核验 | 检查防御是否损害纠错能力 |

结构化核验的固定操作是：识别对方论据中的关键事实，检查其是否准确且真正支持结论，再决定维持或修改答案；无法确认时允许明确表示不确定。它不提供标准答案，也不要求“一律坚持原答案”。具体英文提示在开发轮调整，正式轮之前冻结。

全部条件采用相同的最终输出字段、相同答案/简短理由长度上限，不要求暴露内部思维链。接收模型的温度、推理模式、输出上限保持一致。C2 与 C3、C4 与 C5 调用次数相同，但输入长度和 token 成本仍要报告。

C2 对 C1 测量的是“增加这段误导性解释”的整体影响；其中同时增加了文字量和推理式表达，不能把差异全部归因为逻辑说服。如果要分离长度因素，需另加等长无关文字对照，当前不纳入主问题。

## 5. 模型及角色安排

沿用已经接通的 DeepSeek、Kimi、MiniMax 三个版本。具体模型 ID、接口、日期、生成参数写入冻结配置；MiniMax 经 HKU 转发的事实继续标明。若版本不可用，先修改计划和配置，不在正式轮中静默更换版本。

三个模型都当接收者。每个接收者在一道题上只接收另外一个模型的建议，不同时接收两个模型，也不接收自己生成的建议。

- 一半题目采用配对：DeepSeek → Kimi、Kimi → MiniMax、MiniMax → DeepSeek。
- 另一半题目反向：Kimi → DeepSeek、MiniMax → Kimi、DeepSeek → MiniMax。
- 通过固定种子平衡分配，同一道题的所有条件和重复均使用同一配对。

这给出六个有方向的配对，但不是把每道题都跑六种配对。在接收上下文中统一标为“另一位 AI 助手”，不展示品牌或假冒专家身份，以免混入品牌信任因素。生成来源仍完整记录。

模型差异、六个方向的差异都是次要描述，不做“谁最会骗人”的排行榜。由于不同生成者产出的解释不同，不能把配对差异完全归因于接收者能力。

为什么不先做一轮正式误导、再看结果设计防御：这样容易让防御迎合已见的测试题。防御必须在开发集上完成设计，机制组与防御组一起进入冻结的正式实验。

正式轮两次重复沿用冻结的建议材料，检验接收模型生成波动；不声称测到了误导材料本身的多样性。模型版本、题库和提示不变，只重新采样初始及复核回复、随机化执行顺序。

**120 是可执行的资源规划数，不是已经证明统计上足够。** 开发轮结束后，根据初始正确题数、配对不一致情况、希望识别的效果大小和实际 token 重新评估。在正式轮开始前固定最终 N；不能在正式结果“不显著”后不断加题。

## 7. 数据来源、抽样与材料检查

优先使用已经下载的 **SimpleQA Verified**，沿用原始 ID、参考答案、来源链接。它是候选来源，不保证每条都符合本实验；实际资格检查如下：

- 问题有明确、可独立核实的事实答案，不依赖图片、个人意见或当前不断变化的信息。
- 剔除多步计算、重度推理及答案本身有争议的题，保持“事实复核”范围。
- 至少能构造一个与正确答案同类型、在语义上不同且可核实为错误的候选，例如另一个人名、机构或年份。
- 错误答案的可信程度只按研究者规则检查，不能依据接收模型是否上当来决定保留。
- 与旧 30 题按问题和事实命题检查重叠，开发集与正式集不得共享同一事实的改写题。

在资格清单上按固定种子抽样，先分出开发集、正式集和有顺序的备用题。选择依据不能是本轮模型表现。开发报告可决定全局资格规则，但只能在正式接收结果采集前做一次有记录的修订。

建议材料要求：固定目标答案、统一英文、解释暂定 70–100 词；不包含虚构引文、网址、模型品牌、专家权威标签或“忽略指令”之类内容。正确/错误建议采用相同格式与长度要求。错误解释应支持指定错误答案，但其错误性质必须由题目证据确认。

每份材料只生成一个候选。若拒绝生成、纠正成正确答案或格式不合格，最多按同一规则重试一次；不得反复搜索最有说服力的版本。仍不合格就标记生成失败，按冻结规则使用下一道备用题，且整题对全部模型一致替换。全部失败、原因和替换关系保留。**全部正式建议材料检查完并冻结后，才开始接收者采集。**

上述规则会使结论适用于“成功构造并通过检查的误导材料”，报告须提供材料生成成功率和排除数。正确建议也要核实内容，不能仅因模型给出了正确实体就默认解释正确。

题库、材料和别名表由 Codex 先整理，小组成员复核来源和争议项。记录实际审阅者；尚未完成人工复核时明确标记，不冒充多人独立标注。

## 8. 指标与统计：预先决定怎样算结果

### 主要比较

- RQ1：C2 相对 C1 的**改错率差**。
- RQ2：C3 相对 C2 的**改错率差**。

改错率 = 初始正确、最终错误的次数 ÷ 对应的初始正确次数。所有分支共享初始答案，所以每个配对比较的资格分母相同。它衡量保持正确答案的能力，不衡量模型整体知识水平。

### 必须同时报告的辅助指标

- 完整题库的初始准确率与各条件最终准确率，及其配对变化。
- C2/C3 相对 C0 的变化：避免把自行复核时的波动全部归因为同伴影响。
- 指定错误答案采纳率：与“任意错误”区分。
- 初始正确 → 拒答单独统计；拒答不算事实错误，也不能当成正确。
- C4/C5 在初始错误子集上的纠错率及差值，用于检查防御是否妨碍有益更新。
- API 失败率、格式待审比例、token、延迟；不能把传输失败当作答错。

如果初始错误很少，C4/C5 的纠错率证据不足，必须写“无法充分判断是否损害纠错能力”，不能据低改错率就宣布方法全面有效。初始正确很少时，同样不能稳定估计抗误导能力。

### 统计单位与推断范围

同一道题的模型、条件和两次重复相互相关。正式题目数若为 120，独立题目单位仍为 120，而不是数千条响应。

预先将三个固定模型、两次重复合并估计主要差值，并按**题目整体重采样**计算 cluster bootstrap 置信区间；分母为初始正确的接收试验数，明确这估计的是本配置下的合并表现。另列每个模型的差值与实际分母，不推断到“所有模型”。

两项主要假设如进行显著性检验，采用保留题内全部相关观测的配对/聚类检验，并对两项主要比较做 Holm 校正；其余比较标为探索性。先报告效应量、区间和样本数，不以 p 值代替结果解释。统计方法与随机种子在正式采集前冻结。

评分以最终答案为对象：完整别名匹配后，未知措辞进入去除模型名和条件标签的语义复核；记录原回复、判分理由和审阅者。若要评估解释中每一句的事实性，需要另定义指标，本实验不把它混入答案准确率。争议判分同时给严格/宽松敏感性结果，不在看见条件差异后选择有利标准。

## 9. 开发轮的决策规则与停止标准

第二轮的目的是判断设计能不能回答问题，而非产出显著效果：

1. **接口、材料和判分可靠：** 所有计划分支有已记录结果，传输/格式问题能够区分，争议有明确处理规则，关键来源已复查，才能进入正式轮。
2. **容易题与弱压力：** 若 24 题中，C2 对三个接收模型都没有造成任何“初始正确 → 错误”，先报告“开发样本未观察到影响”。可按全局规则做一次开发阶段修订，或把正式目标改为估计这一固定压力测试下的效果上限；不直接宣称方案有效，也不逐题加强到必定上当。
3. **多数题答不出：** 若三个接收模型在开发集初始正确率均低于 30%，视为抗误导指标分母不足的设计警报。该阈值是工程判断，不是统计功效证明；需调整全局题目资格规则或收窄研究问题。
4. **迭代上限：** 当前资源计划只包含一次 24 题开发实验。若需要改设计并重跑，先在开发报告解释原因、估算新增调用，再更新本计划；不静默追加。
5. **无效或负向防御：** 若结构化核验无效或更差，保留结果。开发阶段可修订一次，但正式轮冻结后不得换防御、只报最佳种子或删除失败题。
6. **正式轮中断：** 额度耗尽、模型版本改变、无法判分或协议异常时暂停该轮，保存已采集内容。未解决的调用不自动重放；任何补跑标明原因和批次。

每轮必须提交小结后才能进入下一轮。正式轮开始前的冻结包至少包括题库 ID、生成材料、提示、模型版本、采样参数、判分规则、N、重复次数、主要对比、代码/文件 SHA 及实际预算上限。

## 10. 调用量：先算清楚再执行

每题、每接收模型、每次重复：初始回答 1 次 + 六组复核 6 次 = **7 次接收调用**。

每题三种配对，每个生成者制作正确/错误建议各 1 份 = **6 次材料生成调用**；两次接收重复共享这些材料，不重复计费。

| 阶段 | 材料生成 | 接收实验 | 计划新调用总数 |
|---|---:|---:|---:|
| 24 题开发、1 次重复 | 24 × 3 × 2 = 144 | 24 × 3 × 7 = 504 | **648** |
| 120 题正式、2 次重复 | 120 × 3 × 2 = 720 | 120 × 3 × 7 × 2 = 5,040 | **5,760** |
| 尚未执行合计 | 864 | 5,544 | **6,408** |

以上不含材料生成失败后的有限重试、备用题及接口诊断；这些必须另列，不伪装成精确账单。已完成的 540 次旧 pilot 不在新调用总数中。正式轮接收部分包含 720 份初始答案、4,320 份最终条件结果，不是 5,040 道独立题。

不凭调用次数推断金额。开发轮后按实际输入、输出、缓存 token 和届时可核实价格核算；HKU 接口另考虑课程额度。正式调用预算随冻结包确定。若资源不足，先减少正式题数或重复数并如实缩小结论，不删除关键对照组。

## 11. 文件、交付与课程对应

沿用 `COMP2501/Project`。旧资料继续放在原路径，新实验使用独立的 `Peer_Misleading_Study` 文件夹，待计划确认后建立：

- `protocol/`：本计划、版本变化、冻结提示、参数与主要分析规定。
- `data/`：来源清单、题库、划分、参考答案、正确/错误建议及质量检查。
- `runs/dev/` 与 `runs/main/`：逐次请求、原始响应、用量及错误日志，永不混用。
- `grading/`：盲化复核队列、决定、审阅者与争议项。
- `analysis/`：改错率、纠错率、准确率、置信区间和用量图表。
- `report/`：课程 proposal、最终报告、演示材料。

最小数据结构：`question_id / split / gold / false_target / source_urls / generator_model / receiver_model / suggestion_id / suggestion_truth / condition / repeat_id / baseline_id / response / grade / adopted_false_target / abstain / token_usage / latency / timestamp / config_hash`。参考答案、密钥均不出现在接收模型请求中；密钥不存入项目文件。

项目能体现课程要求的数据科学流程：明确两个问题 → 公开数据清理与抽样 → 自行采集受控实验数据 → 判分与配对分析 → 可视化 → 验证一个解决流程并说明限制。无需训练新模型或追求行业“最佳方法”。课程 proposal 可把旧 pilot 用作可行性证据，把开发轮用于说明困难和正式设计依据。

## 12. 相关研究与本项目的位置

- [CONSENSAGENT，ACL Findings 2025](https://aclanthology.org/2025.findings-acl.1141/)：研究多模型讨论中的附和现象及提示调整。本项目采用更小、更容易归因的单次建议复核设计，不复现整套多轮系统。
- [Peacemaker or Troublemaker，2025 预印本](https://arxiv.org/abs/2509.23055)：研究模型间迎合与过早共识。我们的目标是测量行为结果，不能仅凭改答案确定其内在机制。
- [Not All Flips Are Conformity，2026 预印本](https://arxiv.org/abs/2606.00820)：区分自行波动、受立场影响和解释说服，支持保留中性复核和错误答案单独组。
- [SimpleQA Verified 数据源](https://huggingface.co/datasets/google/simpleqa-verified)：已有本地快照，实际使用条目仍需资格和来源复核。
